This fork modifies the upstream response cookie snapshot (2026-10-18)
to avoid ambiguous CookieJar name lookups during QQ QR authorization.
It also modifies only the radar Web route to require caller
credentials and remove public caching/coalescing, preserving the SDK method,
page parameter and response model. Other recommendation/public routes are
unchanged; no new upstream protocol is introduced.
The source archive includes the exact fork commit with these modifications,
the authenticated play_duration route in web/src/routes/report.py, and the
launcher/build scripts/tests in iwebplus/. source-identity.json records its commit.
The wrapper adds authenticated local transport, lifecycle controls and a frozen runtime; it disables CORS,
redirects, environment configuration and shared/default account seeds.
The wrapper disables only the upstream per-IP rate limiter for authenticated
loopback batches, retaining access and concurrency controls. Preparation
validates and restricts the host storage directory to mode 0700 without
reading or rewriting account credentials.
Unexpected request errors retain only their stage, exception class and code
locations in a private last-error.json; no request or credential values.

This is a separate executable, not code incorporated into the plugin's
TypeScript source. Redis, cloud upload extras, development/documentation
tools, GUI frameworks and a PyPy-only zstandard backend are not bundled.
The CPython zstandard backend and the locked upstream web runtime remain.

The accompanying qqmusic-source-0.8.2-iwebplus.10.tar.gz contains the complete
upstream commit, the launcher/build scripts/tests, the dependency source
distributions, and the fixed PyInstaller source including its bootloader.
The source archive includes the instructions needed to build this module.
Keep the archive, manifest and this licenses directory with the executable
when redistributing it. No separate source-code offer or proprietary
